# Универсальный мониторинг потребительских цен — отдельный контур MCP

**Статус на 27.10.2026: STAGED / NOT DEPLOYED / NO LIVE PUBLISHER.**

## Проверенное состояние

1. Рабочий REMOTE MCP — `alexpmtk-afk/marketplaces-mcp-ru`, `core/combined.py`, `core/remote.py`, `mcp-marketplaces.service`. Официальные кабинеты WB/Ozon и архивы не являются источником пользовательских публичных цен Ninja/Philips/Severin/Panasonic/Tefal.
2. `core/card_monitor.py` содержит **старый** контракт `MARKETPLACE_CARD_BATCH_V1`, Redis namespace `marketplace-card-monitor:v1`, четыре инструмента `card_monitor_*` и вход `/card-monitor/ingest` с отдельным токеном. В его контракте есть поля `size` и `studded`, исторически связанные с шинами. Он НЕ доказывает рейтинг, число отзывов и точную модель новой универсальной задачи.
3. Новый исходный код находится в отдельном приватном репозитории `alexpmtk-afk/marketplace-card-monitor`, ветка `fix/review-scope-home-20261027`. Исполнитель — браузер HOME, собственная SQLite, локальные диагностика/очередь, Google Sheets v4. На HOME нет подтверждённой фоновой OAuth-авторизации; новое задание Windows не включено. Репозиторий не содержит отдельного MCP-сервера.
4. Google Sheets `Мониторинг цен` — **канонические** реестр заданий и принятая история цен, ID `176qSt6WaldOvnktJepBBvzudgh1IkdffxaP8eHhYIOU`. Шесть спорных ценовых записей убраны из видимых историй в резерв, потому что точность области рейтинга/отзывов не доказана. Все старые данные сохранены вне GitHub.

## Согласованные границы системы

`Google Sheets (товары) -> HOME (Яндекс, поиск, доказательства) -> локальная SQLite (диагностика/карантин/очередь) -> Google Sheets (доставка и чтение обратно) -> REMOTE MCP (только зеркало для запросов)`.

- **ChatGPT** — основная разработка, контракт, изменения GitHub и таблиц, проверка и приёмка.
- **Codex HOME** — узкие действия, требующие реальной Windows/браузера/локальных файлов. Не становится владельцем проекта.
- **GitHub** — версионный код, тесты, схема, правила. Не заменяет Google Sheets как журнал цен; токены и персональные данные не хранятся.
- **REMOTE MCP** — интерфейс к проверенным результатам, без собственного браузерного сбора и без подмены канонической истории.
- **Старый мониторинг шин** и его Redis `marketplace-card-monitor:v1`, установки, службы, задачи и история не меняются.

## Что уже подготовлено в ветке MCP

Модуль `core/universal_price_monitor.py` и регистрация в `core/combined.py`: три инструмента только для чтения:

- `universal_price_monitor_status` — пока возвращает `NOT_CONNECTED`, если самостоятельный поставщик данных не настроен.
- `universal_price_monitor_latest` — только наблюдения с подтверждённым рейтингом >= 4,8, >=10 именно **отзывов**, совпадением модели и условиями цены.
- `universal_price_monitor_history` — только соответствующие этому же правилу исторические наблюдения.

Выделен независимый Redis namespace `universal-price-monitor:v1`. **Сейчас нет кода и разрешения на запись из HOME в него.** Отдельный проверенный, аутентифицированный источник публикации — следующий этап. Нельзя использовать `/card-monitor/ingest` и старые ключи как обходной путь.

## Договорённость о доказательствах

- Рейтинг и минимум 10 реальных текстовых отзывов должны быть относятся к **выбранной модели/варианту**, не продавцу, не склеенной карточке и не числу оценок.
- Цена Ozon — только доказанное условие `С банками`; Wildberries — одна доказанная цена `с WB Кошельком` на одно предложение и момент измерения.
- Запись в основном Google Sheets допускается только после этих проверок. Повторные измерения другого времени допустимы; дубли внутри одного измерения запрещены.
- `sheets_readback=MATCH` должно подтверждаться только **после** реального чтения уже записанных строк. Один флаг или утверждение HOME не являются независимым доказательством; нужно обеспечить проверяемую подпись/хэш фактического наблюдения.
- REMOTE MCP **не должен** выдавать заявление о независимой проверке источника, если прочёл лишь сообщение HOME. Поэтому инструмент возвращает `PRODUCER_ATTESTED`, а не `INDEPENDENTLY_VERIFIED`.
- Если подключение отсутствует, инструменты возвращают `NOT_CONNECTED` либо `NO_VERIFIED_DATA`, а не старые цены под видом текущих.

- WB VERITAS, артикул 898477205: при выборе конкретного варианта сайт пишет «У этого варианта пока нет отзывов и оценок»; общий рейтинг 4,7/64 оценки не относится доказанно к выбранному варианту.
- WB PREMIUM BOX: показатель 4,9 относится к продавцу, собственные отзывы товара отсутствуют.
- Ozon HomeTech / МобиРус: 5/104 и 5/46, а также цены с банковским условием видны на страницах, но модельная исключительность отзывов не подтверждена. Это не является доказательством их реального смешения.
- Сетевой `ERR_TIMED_OUT` на Ozon и WB возник при дополнительном тестировании; повторные попытки остановлены без настройки туннелей.
- Официальный отчёт WB «Оценка товара» доступен продавцу по **его собственным товарам**, а не является универсальным открытым отчётом по чужим карточкам конкурентов. Не использовать как доказательство по товарам, на которые у владельца нет соответствующих прав.

**Обязательная реакция MCP:** показывать `NOT_CONNECTED` или `NO_VERIFIED_DATA`, хранить отрицательную диагностику отдельно и не объявлять успешно наблюдаемой ни одной цены, у которой не доказан точный рейтинг и минимум 10 отзывов нужного варианта.

## Дальнейшие технические этапы

1. **HOME read-only acceptance**: определить реальную рабочую ветку и SHA, конкретную SQLite, статус Windows task, наличие MCP-сервиса HOME, запущенный сборщик, наличие непереданных наблюдений и OAuth **без чтения секретов**. Сверить локальные изменения с уже перенесённым GitHub `fix/review-scope-home-20261027`.
2. **Точные отзывы**: через разрешённый публичный интерфейс выяснить, существует ли рейтинговый показатель и количество именно отзывов выбранной модели. Если нет — фиксировать `UNPROVEN`, не пустую «успешную» историю.
3. **OAuth HOME**: настроить отдельный долговременный доступ именно к канонической таблице (не использовать OAuth инструментов ChatGPT), шифрование DPAPI для текущего пользователя и восстановление доступа.
4. **REMOTE mirror transport**: отдельная, выключенная по умолчанию авторизованная публикация **только после** завершённой Google-доставки, с проверкой схемы, idempotency key, ограничениями объёма и явным подтверждением обратного чтения. Ни токены, ни секреты в GitHub. Это не production deployment.
5. **Приёмка**: проверки инструментария MCP, схемы, старых ключей (не изменились), отсутствия утечек, реальных записей, ошибок доставки, восстановления после падения, сортировки цен, контроля времени, повтора загрузки, старого монитора. Отдельно запрашивать разрешение владельца на merge/restart REMOTE, регистрацию новой задачи Windows, а также на выдачу постоянных учётных данных.
